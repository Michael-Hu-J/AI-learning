# 第 3 篇：三层定位降级策略：让测试不再脆弱
> **代码说明**：本文中的代码示例来自完整版系统，配套代码（`配套代码/` 目录）提供了功能一致的简化版——去掉了 LLM API、LangGraph、数据库等外部依赖，替换为纯规则实现 + JSON 文件 + 内置演示应用。文章讲原理，配套代码可本地跑通，两相对照效果更好。

> 在 UI 自动化测试中，最脆弱的是什么？不是测试逻辑，而是元素选择器。前端一次简单的重构，就可能导致几十个测试用例失败。下面拆分 AI测试系统中的三层定位降级策略，看看怎么让测试从"脆弱"变得"坚韧"。

> 这篇示例基于一个本地电商秒杀演示系统（`http://127.0.0.1:5000`），仅用于说明策略原理。

> **配套代码获取**：这篇涉及的完整代码在 `配套代码/tests/test_locator.py` 和 `locator/resolver.py` 中。  
> **增补**：`locator_tiers` JSON 契约见 `配套代码/examples/locator_tiers_example.json`。

## 一、为什么选择器会失效？

### 1.1 选择器失效的四大原因

**原因 1：前端重构**

```html
<!-- 旧版本 -->
<button id="login-btn" class="btn-primary">登录</button>

<!-- 新版本：ID 被移除 -->
<button class="btn btn-login">登录</button>

<!-- 测试脚本失败 -->
page.click("#login-btn")  #  Element not found
```

**原因 2：动态 ID/Class**

```html
<!-- React/Vue 生成的动态 ID -->
<div id="root">
  <input id="input-1683245678-abc123" class="css-1a2b3c" />
</div>

<!-- 每次刷新页面，ID 都不同 -->
page.fill("#input-1683245678-abc123", "testuser")  #  下次运行失败
```

**原因 3：A/B 测试**

```html
<!-- 版本 A -->
<button id="submit-btn">提交</button>

<!-- 版本 B -->
<button id="confirm-btn">确认提交</button>

<!-- 测试脚本只能匹配其中一个 -->
page.click("#submit-btn")  #  版本 B 失败
```

**原因 4：国际化（i18n）**

```html
<!-- 中文 -->
<button>登录</button>

<!-- 英文 -->
<button>Login</button>

<!-- 测试脚本使用 text= 定位 -->
page.click("text=登录")  #  英文环境失败
```

### 1.2 传统解决方案的局限性

**方案 1：使用 XPath**

```python
# 绝对 XPath（脆弱）
page.click("/html/body/div[1]/form/button")  #  DOM 结构变化即失效

# 相对 XPath（稍好，但仍脆弱）
page.click("//button[@id='login-btn']")  #  ID 变化即失效
```

**方案 2：使用 CSS 选择器**

```python
# ID 选择器（最脆弱）
page.click("#login-btn")  #  ID 变化即失效

# Class 选择器（较好，但仍可能变化）
page.click(".btn-primary")  #  Class 变化即失效
```

**方案 3：使用 data-testid**

```html
<!-- 需要前端配合添加 -->
<button data-testid="login-btn">登录</button>

<!-- 测试脚本 -->
page.click("[data-testid='login-btn']")  #  稳定，但需要前端配合
```

**问题**：以上方案都是"单一策略"，一旦失效，测试直接失败，没有降级机制。

## 二、三层定位降级策略架构

### 2.1 策略总览

我们的解决方案是**三层降级 + 缓存**：

```
┌─────────────────────────────────────────────────────────┐
│  CACHE 缓存层（最快）                                     │
│  - 查询历史定位记录                                       │
│  - LRU 淘汰（最近使用优先保留）                           │
│  - 命中则直接返回，无需尝试                               │
└────────────────────┬────────────────────────────────────┘
                     │ 未命中
                     ▼
┌─────────────────────────────────────────────────────────┐
│  L1 稳定选择器（最可靠）                                  │
│  - 原始选择器（用户指定）                                 │
│  - data-testid / data-test / data-qa                    │
│  - role + text 组合                                     │
│  - text= / button:has-text() / a:has-text()             │
└────────────────────┬────────────────────────────────────┘
                     │ 全部失败
                     ▼
┌─────────────────────────────────────────────────────────┐
│  L2 DOM 推断（中等可靠）                                  │
│  - 部分属性匹配（contains）                               │
│  - ID/Class/Name/Placeholder 模糊匹配                    │
│  - XPath contains() 函数                                │
└────────────────────┬────────────────────────────────────┘
                     │ 全部失败
                     ▼
┌─────────────────────────────────────────────────────────┐
│  L3 AI 辅助（最后手段）                                   │
│  - 关键词提取 + 组合生成                                  │
│  - LLM 生成候选选择器（可选）                             │
│  - 最多 20 个候选                                         │
└────────────────────┬────────────────────────────────────┘
                     │ 全部失败
                     ▼
┌─────────────────────────────────────────────────────────┐
│  NONE 定位失败                                            │
│  - 触发自愈系统                                           │
│  - 记录失败历史                                           │
│  - 通知用户                                               │
└─────────────────────────────────────────────────────────┘
```

### 2.2 核心代码结构

```python
# ui_locator_resolver.py - 三层定位解析器
from typing import Dict
from collections import OrderedDict

class UILocatorResolver:
    """Playwright 元素定位策略解析器。"""
    
    MAX_CACHE_SIZE = 500
    
    def __init__(self, enable_l3_ai: bool = False):
        self._enable_l3_ai = enable_l3_ai
        self._locator_cache = OrderedDict()  # LRU 缓存
    
    def resolve(self, page, step) -> Dict:
        """主入口：尝试三层定位策略"""
        target = step.get("target", "")
        value = step.get("value", "")
        hints = step.get("locator_hints", {})
        action = step.get("action", "")
        page_url = page.url
        
        # 1. 查缓存
        cached = self._resolve_cache(page_url, action, target)
        if cached:
            return {"found": True, "selector": cached, "level": "CACHE"}
        
        # 2. L1 稳定选择器
        l1_candidates = self._build_l1_candidates(target, value, hints)
        selector, attempts = self._first_working_selector(page, l1_candidates, "L1")
        if selector:
            self._set_cache(page_url, action, target, selector)
            return {"found": True, "selector": selector, "level": "L1"}
        
        # 3. L2 DOM 推断
        l2_candidates = self._build_l2_candidates(target, value)
        selector_l2, attempts_l2 = self._first_working_selector(page, l2_candidates, "L2")
        if selector_l2:
            self._set_cache(page_url, action, target, selector_l2)
            return {"found": True, "selector": selector_l2, "level": "L2"}
        
        # 4. L3 AI 辅助（可选）
        if self._enable_l3_ai:
            all_attempts = attempts_l1 + attempts_l2
            l3_candidates = self._build_l3_candidates(target, value, all_attempts)
            selector_l3, attempts_l3 = self._first_working_selector(page, l3_candidates, "L3")
            if selector_l3:
                self._set_cache(page_url, action, target, selector_l3)
                return {"found": True, "selector": selector_l3, "level": "L3"}
        
        return {"found": False, "selector": "", "level": "NONE"}
```

## 三、L1 稳定选择器：最可靠的定位策略

### 3.1 L1 候选生成规则

L1 层尝试最稳定的选择器，按优先级生成候选：

```python
def _build_l1_candidates(self, target, value, hints):
    candidates = []
    
    # 1. 原始选择器（用户指定的）
    if target:
        candidates.append(target)
        if target.startswith("//"):
            candidates.append(f"xpath={target}")
    
    # 2. data-testid 系列（最稳定的测试属性）
    test_id = hints.get("testid") or hints.get("data-testid")
    if test_id:
        candidates.extend([
            f"[data-testid='{test_id}']",
            f"[data-test='{test_id}']",
            f"[data-qa='{test_id}']",
        ])
    
    # 3. role + text 组合（语义化定位）
    role = hints.get("role")
    text = hints.get("text") or value
    if role:
        if text:
            candidates.append(f"role={role}[name='{text}']")
        candidates.append(f"role={role}")
    
    # 4. label 定位（表单元素）
    label = hints.get("label")
    if label:
        candidates.append(f"label={label}")
    
    # 5. text= 定位（文本内容）
    if text:
        candidates.extend([
            f"text={text}",
            f"button:has-text('{text}')",
            f"a:has-text('{text}')",
        ])
    
    return self._dedup(candidates)
```

**场景**：定位登录页面的"登录"按钮

```html
<!-- 页面结构 -->
<form id="login-form">
  <input id="username" type="text" placeholder="用户名" />
  <input id="password" type="password" placeholder="密码" />
  <button type="submit" data-testid="login-submit">登录</button>
</form>
```

**L1 候选生成**：

```python
# 输入

value = "登录"
hints = {
    "testid": "login-submit",
    "role": "button",
    "text": "登录"
}

# L1 候选列表（按优先级）
candidates = [
    "#login-btn",                          # 1. 原始选择器（失败）
    "xpath=//button[@type='submit']",      # 2. XPath 变体（失败）
    "[data-testid='login-submit']",        # 3. data-testid  成功！
    "[data-test='login-submit']",
    "[data-qa='login-submit']",
    "role=button[name=\"登录\"]",
    "role=button",
    "text=登录",
    "button:has-text('登录')",
    "a:has-text('登录')",
]
```

### 3.3 为什么 data-testid 最稳定？

选择器稳定性从高到低排序：

- **data-testid**（高）— 专门用于测试，前端不会随意修改
- **text=**（中）— 文本内容可能国际化
- **role=**（中）— ARIA 角色可能变化
- **xpath**（低）— DOM 结构变化即失效
- **class**（低）— CSS 类名经常变化
- **id**（低）— 前端重构时 ID 常被修改

**最佳实践**：

```html
<!-- 推荐：添加 data-testid -->
<button data-testid="login-submit" id="login-btn" class="btn-primary">
  登录
</button>

<!-- 测试脚本 -->
page.click("[data-testid='login-submit']")  #  最稳定
```

## 四、L2 DOM 推断：中等可靠性的降级策略

### 4.1 L2 候选生成规则

当 L1 全部失败时，进入 L2 层，使用 DOM 属性推断：

```python
def _build_l2_candidates(self, target, value):
    candidates = []
    
    # 1. 从原始选择器提取关键词
    if target:
        # 提取 #username 中的 "username"
        token = target.strip().lstrip("#.").split()[0]
        token = re.sub(r"[^a-zA-Z0-9_-]", "", token)
        
        if token:
            candidates.extend([
                f"[id*='{token}']",              # ID 包含
                f"[class*='{token}']",           # Class 包含
                f"[name*='{token}']",            # Name 包含
                f"[placeholder*='{token}']",     # Placeholder 包含
                f"//*[@id and contains(@id, '{token}')]",   # XPath ID 包含
                f"//*[@class and contains(@class, '{token}')]",  # XPath Class 包含
            ])
            candidates.append(f"xpath=//*[@id and contains(@id, '{token}')]")
            candidates.append(f"xpath=//*[@class and contains(@class, '{token}')]")
    
    # 2. 从 value 提取关键词
    if value:
        safe = value.replace("'", "\\'").strip()
        if safe:
            candidates.extend([
                f"xpath=//*[contains(text(), '{safe}')]",
                f"xpath=//*[contains(@placeholder, '{safe}')]",
            ])
    
    return self._dedup(candidates)
```

### 4.3 contains() 的力量

`contains()` 是 XPath 和 CSS 中的模糊匹配函数：

```python
# CSS contains（部分匹配）
"[id*='username']"      # ID 包含 username
"[class*='form']"       # Class 包含 form
"[name*='user']"        # Name 包含 user
"[placeholder*='密码']"  # Placeholder 包含密码

# XPath contains
"//*[@id and contains(@id, 'username')]"
"//*[contains(text(), '登录')]"
"//*[contains(@placeholder, '用户名')]"
```

**优势**：
- 不依赖完整的 ID/Class
- 部分匹配即可
- 适合动态生成的属性

**劣势**：
- 可能匹配到多个元素
- 性能比精确匹配差

## 五、L3 AI 辅助：最后手段

### 5.1 L3 候选生成规则

当 L1 和 L2 都失败时，进入 L3 层（可选开关）：

```python
def _build_l3_candidates(self, target, value, attempts):
    """L3 AI 辅助候选生成（可选开关）。"""
    if not self._enable_l3_ai:
        return []
    
    candidates = []
    
    # 1. 从失败历史提取关键词
    tokens = []
    for item in attempts:
        raw = item.get("selector", "")
        tokens.extend(re.findall(r"[a-zA-Z][a-zA-Z0-9_-]{2,}", raw))
    tokens.extend(re.findall(r"[a-zA-Z][a-zA-Z0-9_-]{2,}", target or ""))
    tokens.extend(re.findall(r"[a-zA-Z][a-zA-Z0-9_-]{2,}", value or ""))
    
    # 2. 组合生成候选
    seen = set()
    for tk in tokens:
        low = tk.lower()
        if low in seen:
            continue
        seen.add(low)
        candidates.extend([
            f"[id*='{low}']",
            f"[class*='{low}']",
            f"xpath=//*[contains(@id, '{low}') or contains(@class, '{low}') or contains(text(), '{low}')]",
        ])
    
    # 3. LLM 生成候选（可选）
    llm_candidates = self._query_llm_candidates(target, value, attempts)
    candidates.extend(llm_candidates)
    
    return self._dedup(candidates)[:20]
```

### 5.2 LLM 生成候选

> 配套代码已将 L3 简化为纯规则启发式（去掉了 DashScope LLM 调用），以降低依赖。文中保留完整的 LLM 调用代码，展示生产环境的原始实现。

```python
def _query_llm_candidates(self, target, value, attempts):
    """L3 真实模型候选生成（DashScope）。"""
    api_key = os.getenv("DASHSCOPE_API_KEY", "").strip()
    if not api_key:
        return []
    
    # 构建提示词
    prompt = (
        "你是 UI 自动化元素定位专家。"
        "请根据失败历史和目标语义输出最多 8 个 Playwright 可用选择器，"
        "仅输出 JSON 数组字符串，不要解释。"
        f"\n目标 selector: {target or '-'}"
        f"\n目标文本/值: {value or '-'}"
        f"\n失败尝试: {json.dumps(attempts, ensure_ascii=False)}"
    )
    
    # 调用 DashScope API
    resp = httpx.post(
        "https://dashscope.aliyuncs.com/api/v1/services/aigc/text-generation/generation",
        headers={"Authorization": f"Bearer {api_key}"},
        json={
            "model": "qwen-plus",
            "input": {
                "messages": [
                    {"role": "system", "content": "只输出 JSON 数组，不输出任何解释"},
                    {"role": "user", "content": prompt},
                ]
            },
            "parameters": {"temperature": 0.1, "max_tokens": 512},
        },
        timeout=15.0,
    )
    
    # 解析响应
    data = resp.json()
    content = data.get("output", {}).get("choices", [{}])[0].get("message", {}).get("content", "")
    arr = json.loads(content)
    return [str(x).strip() for x in arr if str(x).strip()]
```

### 5.4 L3 的优缺点

**优点**：
- 利用 LLM 的语义理解能力
- 可以生成复杂的 XPath
- 适合极端情况

**缺点**：
- 需要 API Key（DashScope）
- 有延迟（1-3 秒）
- 有成本（每次调用约 0.01 元）
- 可能生成无效选择器

**建议**：
- 默认关闭（`enable_l3_ai=False`）
- 在关键场景手动开启
- 缓存 L3 结果，避免重复调用

## 六、LRU 缓存机制：避免重复查找

### 6.1 为什么需要缓存？

**问题场景**：

```python
# 步骤 1：定位 #username
resolution = resolver.resolve(page, {"action": "输入文本", "target": "#username"})
# → 尝试 L1: #username  成功（耗时 50ms）

# 步骤 2：再次定位 #username（同页面）
resolution = resolver.resolve(page, {"action": "输入文本", "target": "#username"})
# → 尝试 L1: #username  成功（耗时 50ms）← 重复查找！

# 步骤 3：再次定位 #username（同页面）
resolution = resolver.resolve(page, {"action": "输入文本", "target": "#username"})
# → 尝试 L1: #username  成功（耗时 50ms）← 重复查找！
```

**解决方案**：缓存定位结果

```python
# 步骤 1：缓存未命中，尝试 L1
resolution = resolver.resolve(page, {"action": "输入文本", "target": "#username"})
# → L1: #username  成功 → 写入缓存（耗时 50ms）

# 步骤 2：缓存命中，直接返回
resolution = resolver.resolve(page, {"action": "输入文本", "target": "#username"})
# → CACHE: #username  命中（耗时 1ms）← 快 50 倍！

# 步骤 3：缓存命中，直接返回
resolution = resolver.resolve(page, {"action": "输入文本", "target": "#username"})
# → CACHE: #username  命中（耗时 1ms）← 快 50 倍！
```

### 6.2 LRU 缓存实现

```python
from collections import OrderedDict

class UILocatorResolver:
    MAX_CACHE_SIZE = 500
    
    def __init__(self):
        self._locator_cache = OrderedDict()
    
    def _resolve_cache(self, page_url, action, target):
        """查询定位缓存，命中则返回 selector，否则返回空字符串。"""
        key = f"{page_url}:{action}:{target}"
        if key in self._locator_cache:
            # 移到末尾（最近使用）
            self._locator_cache.move_to_end(key)
            return self._locator_cache[key]
        return ""
    
    def _set_cache(self, page_url, action, target, selector):
        """写入定位缓存，LRU 淘汰。"""
        key = f"{page_url}:{action}:{target}"
        if key in self._locator_cache:
            # 移到末尾
            self._locator_cache.move_to_end(key)
        else:
            # 新条目
            if len(self._locator_cache) >= self.MAX_CACHE_SIZE:
                # 淘汰最旧的（首元素）
                self._locator_cache.popitem(last=False)
        self._locator_cache[key] = selector
```

### 6.3 缓存键设计

缓存键 = `page_url:action:target`，每个组合唯一标识一次定位：

- **登录页输入用户名** → `http://127.0.0.1:5000/login:输入文本:#username`
- **登录页点击登录** → `http://127.0.0.1:5000/login:点击元素:#loginForm button[type=submit]`
- **注册页输入用户名** → `http://127.0.0.1:5000/register:输入文本:#username`（不同页面，不同缓存）

**为什么包含 page_url？**

```html
<!-- 登录页 -->
<input id="username" />

<!-- 注册页 -->
<input id="username" class="form-input" />

<!-- 不同页面的 #username 可能不同 -->
```

### 6.4 缓存统计

```python
# 缓存命中统计（伪代码示意）
cache_hits = 0
cache_misses = 0

def resolve(self, page, step):
    global cache_hits, cache_misses
    
    page_url = page.url
    action = step.get("action", "")
    target = step.get("target", "")
    cached = self._resolve_cache(page_url, action, target)
    if cached:
        cache_hits += 1
        return {"found": True, "selector": cached, "level": "CACHE"}
    
    cache_misses += 1
    # ... 尝试 L1/L2/L3
```

**实际数据**（一次典型执行）：

- 总定位次数：15 次
- 缓存命中：8 次（平均耗时 1ms）
- 缓存未命中：7 次（平均耗时 50ms）
- 命中率：53.3%，节省时间约 350ms

## 八、踩坑经验

### 8.1 坑 1：缓存污染

**问题**：页面刷新后，缓存中的选择器可能失效。

**解决**：缓存键包含 page_url，页面变化时缓存自动失效。

```python
# 登录页的缓存
key1 = "http://127.0.0.1:5000/login:点击元素:#login-btn"

# 注册页的缓存
key2 = "http://127.0.0.1:5000/register:点击元素:#login-btn"

# 不同页面，不同缓存
```

### 8.2 坑 2：L3 延迟过高

**问题**：LLM 调用需要 1-3 秒，影响测试性能。

**解决**：默认关闭 L3，关键场景手动开启。

```python
# 默认关闭
resolver = UILocatorResolver(enable_l3_ai=False)

# 关键场景开启
resolver = UILocatorResolver(enable_l3_ai=True)
```

### 8.3 坑 3：候选列表过长

**问题**：L1/L2/L3 生成大量候选，尝试耗时。

**解决**：每个候选超时 1.2 秒，最多尝试 20 个。

```python
def _first_working_selector(self, page, candidates, level, timeout_ms=1200):
    attempts = []
    for selector in candidates:
        try:
            locator = page.locator(selector).first
            locator.wait_for(state="attached", timeout=timeout_ms)
            return selector, attempts
        except Exception:
            pass
    return "", attempts
```

### 8.4 坑 4：去重逻辑不完善

**问题**：候选列表中有重复项，浪费尝试时间。

**解决**：使用 set 去重。

```python
@staticmethod
def _deduplicate(items):
    seen = set()
    result = []
    for item in items:
        it = item.strip()
        if not it or it in seen:
            continue
        seen.add(it)
        result.append(it)
    return result
```

## 九、写在最后

三层定位降级策略是我在这个项目里最满意的设计之一。它的核心思想很简单：**不要依赖单一选择器，而是准备一个候选列表，逐个尝试，直到找到能用的那个**。

实际跑下来，L1（data-testid / role+text）覆盖了 80% 以上的场景，L2（contains 模糊匹配）解决了动态 ID 的问题，L3（AI 辅助）虽然用得少，但在极端情况下确实能救命。缓存层则让重复定位从 50ms 降到 1ms。

拆了一遍策略，核心就三个 takeaway：

**第一，别相信前端不会改。** 我们最开始只用 CSS 选择器，觉得"这个按钮的 ID 不会变吧"。结果前端重构了一次，所有 ID 都加了前缀，200 多个测试用例挂了 80 个。三层定位的本质是承认一个事实：前端一定会改，你要做的是让测试能自动适应，而不是每次都要人肉修选择器。

**第二，data-testid 是最便宜的投资。** 让前端加一个 `data-testid="login-btn"`，成本是 5 秒钟。但这个属性能让你的测试稳定性从 60% 提升到 90%+。我们项目里 L1 命中率从 60% 涨到 90%+，不是靠算法改进，是靠前端配合加了 200 多个 testid。算法能解决的问题有限，流程上的小事往往比技术上的大事影响更大。

**第三，缓存不是优化，是必须。** 同一个选择器在一次测试里可能被尝试多次——定位失败、重试、再定位。每次尝试都要遍历 DOM，50ms 看起来不多，但 100 次尝试就是 5 秒。LRU 缓存把重复定位降到 1ms，一次测试能省 3-4 秒。一千个用例跑下来就是 3000-4000 秒的差异——50 分钟和 10 分钟的区别。

配套代码里的 `locator/resolver.py` 是这套策略的完整实现，去掉了 LLM 部分（L3），用纯规则启发式替代。`tests/test_locator.py` 有 8 个测试用例覆盖所有层级。先跑通测试，再看代码理解逻辑。

下一篇讲 AI 自愈系统，这是三层定位的"后手"——当所有候选都失败时，系统如何自动诊断错误并尝试修复。
