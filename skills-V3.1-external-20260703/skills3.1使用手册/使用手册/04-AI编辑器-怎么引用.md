# 在 Cursor 里怎么「@」它，才不会瞎聊

专业版有一半价值在 **SKILL 文档**：告诉 AI「先做什么、后做什么、输出长什么样」。

用不对，就会觉得「和网页版 GPT 差不多」；用对了，才会稳定产出能进评审的测试点和能跑的 spec。

> **命令与环境**：以 zip 内 **`README.md`** 为准。本篇只讲编辑器用法。

---

## 第一步：打开对的文件夹

在 Cursor（或 Trae、其他支持 `@` 的编辑器）里：

**File → Open Folder → 选 `skills-专业版V3.0` 根目录**

判断对不对：左侧文件树顶层能看到 `generate.sh`、`templates/`、`api-skills/`（与 `01` 目录图一致）。

不要只打开子目录 `api-skills`，否则 @ 路径容易错、AI 可能编造不存在的文件。

可选：包内 `.cursor/rules/` 会在本工作区给 AI 一些测试术语约束（专业版、pytest 等）。**不必人工背诵**，打开根目录即可生效。

### 操作自检（对照你的界面）

| 检查项 | 正确时大致长这样 |
|--------|------------------|
| 窗口标题 / 工作区名 | 显示 `skills-专业版V3.0` 或你解压后的文件夹名 |
| 左侧根级文件 | 能看见 `generate.sh`、`README.md`、`START_HERE.md` |
| Chat 里输入 `@` | 补全列表出现包内路径，如 `testcase-skills/生成/SKILL.md` |
| 第一次试跑 | 用下面「示例一」话术，产出写到 `output/` 里某个 `.md` |

若 `@` 补全里没有 `SKILL.md`，几乎总是 **Open Folder 选错层级**——关掉工作区，重新选含 `generate.sh` 的那一层。

## 第二步：@ 要具体到文件

| 不推荐 | 推荐 |
|--------|------|
| 「帮我写接口测试」 | `@api-skills/执行/SKILL.md` + 你的 OpenAPI 或 base_url |
| 「写用例」 | `@testcase-skills/生成/SKILL.md` + PRD 文件 |
| 「记个 bug」 | `@bug-reporter/SKILL.md` + 失败日志 |

`@` 后面跟的是**包内相对路径**。编辑器会补全，优先选带 `SKILL.md` 的条目。

索引文件（如 `api-skills/索引.md`）适合**人读流程**；执行时仍 @ 具体阶段的 `SKILL.md`。

## 第三步：说清输入、输出、约束

好的任务描述通常包含：

1. **输入材料** —— PRD 路径、OpenAPI、URL、账号说明（**脱敏**）  
2. **输出路径** —— 例如 `output/xxx.md`、`output/xxx.py`  
3. **范围** —— 只做冒烟 / 只做登录模块 / 不要造性能脚本  

示例一：从 PRD 出测试点（无需后端）

```text
@testcase-skills/生成/SKILL.md
@examples/prd_mini_seckill_auth.md

按专业版规则生成测试用例，输出到 output/seckill_auth_testcases.md
```

示例二：接口冒烟 spec

```text
@api-skills/执行/SKILL.md

base_url: http://localhost:5000
为 POST /api/login、GET /api/user/profile 生成 api_pytest spec，
保存到 output/api_auth_smoke.md，然后告诉我如何用 generate.sh 生成脚本。
```

示例三：失败写缺陷

```text
@bug-reporter/SKILL.md

根据下面 pytest 失败摘要写缺陷 Markdown，严重度你先按现象估一版：

（粘贴 -v 失败的几行）
```

## 隐私与公司合规

- PRD、OpenAPI、截图里的**真实账号、密钥、内网域名**先打码再 @；练手可用 `examples/` 样例。  
- 若公司禁止需求原文上公网模型：用企业/本地模型，或改走声明式线（自己写 spec，不上传 PRD）。  
- 生成物进 Git 前再过一眼，避免把 Secret 写进 spec。

## 两种模式对照（再强调一次）

| 模式 | 何时用 |
|------|--------|
| **只跑 generate.sh** | spec 已写好或改模板即可 |
| **AI + @ SKILL** | 从 PRD/OpenAPI/自然语言到 spec、用例、缺陷 |

常见做法：AI 出 spec → 人改 base_url → `./generate.sh` → CI 只跑 pytest。

---

## 和「意图路由」的关系

一句话需求很模糊时，先 @ `intent-router/SKILL.md` 或自己判断走哪条线（第 5 篇）。  
例如说「做自动化」，要先澄清是 **接口**、**页面** 还是 **App**。

---

## 三个翻车现场

1. **没打开包根目录** —— AI 编造不存在的 SKILL 路径。  
2. **只 @ 索引不 @ 执行 SKILL** —— 输出格式飘。  
3. **没说输出路径** —— 文件散落在聊天里，不好进 Git。

## 话术库在哪

包内两个位置存放可直接复制的话术：

| 文件 | 用途 |
|------|------|
| `prompts/常用话术.md` | 13 条完整话术（用例、需求建模、评审、API/UI、缺陷、压测、路由） |
| `START_HERE.md` | 第一次打开包时的三条短流水线 |

打开 `skills-专业版V3.0` 根目录 → 左侧展开 `prompts/` 即可。**以你 zip 内文件为准**，发版后可能增删条目。
