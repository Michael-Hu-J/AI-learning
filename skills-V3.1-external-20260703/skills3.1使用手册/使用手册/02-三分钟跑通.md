# 3 分钟验收：你没后端也能证明「流程是通的」

> **命令以 zip 内 `README.md` 为准**（与本篇一致处可直接照做）。完整 Day 1 清单见 `00-系列导读.md`。

不少同学解压后第一件事是跑全量 pytest，然后盯着 `Connection refused` 发呆，以为包坏了。

其实专业版可以分两步验收：

1. **生成流程** —— spec 能不能变成 `.py`  
2. **执行流程** —— pytest 能不能收集到用例（**不必**全部 PASSED）

这篇按「无后端」场景写，有服务的同学看到 **3b** 即可。

---

## 第 0 步：确认 Python

终端执行：

```bash
python3 --version
```

需要 **Python 3.8+**。Windows 若只有 `python`，可试：

```bash
python --version
```

没有的话去 [python.org](https://www.python.org/downloads/) 安装，装时勾选「Add to PATH」。

---

## 第 1 步：进入正确目录

解压后 `cd` 到**含有 `generate.sh` 的那一层**（目录名可能是 `skills-专业版V3.0`）。

---

## 第 2 步：安装最小依赖

```bash
python3 -m pip install pytest requests PyYAML
```

`generate.sh` 会用到 PyYAML；API 冒烟需要 pytest 和 requests。  
UI / 压测等以后按需再装，见包内 `README.md` 依赖表。

---

## 第 3 步：生成第一个脚本

**Linux / macOS：**

```bash
chmod +x generate.sh    # 只需一次
./generate.sh templates/api_smoke.md
```

**Windows（无执行权限时）：**

```bash
bash generate.sh templates/api_smoke.md
```

成功时终端应出现类似「已生成」「OK」和 `output/api_smoke.py` 路径。

### 终端一个字都没有？

在部分 IDE 集成终端里，生成其实成功了，只是**不显示字**。按顺序自查：

```bash
ls -la output/api_smoke.py          # 看时间是否刚更新
cat output/.last_run_message.txt    # 应有完整提示全文
cat output/.last_generate_ok        # 仅时间戳 + 路径
```

### Permission denied

```bash
chmod +x generate.sh
# 或
bash generate.sh templates/api_smoke.md
```

---

## 第 4 步：pytest 分三档跑

**仍在包根目录**操作；下面路径假设已 `cd output`。

### 3a —— 推荐先做（不访问网络，几秒）

```bash
cd output
python3 -m pytest api_smoke.py --collect-only -q
```

期望看到 **`N tests collected`**（无报错即可；内置 `api_smoke.md` 条数随版本扩展，以终端为准）。

**走到这里，就说明环境与生成流程已就绪。**

### 3b —— 有真实后端时

```bash
export TEST_BASE_URL=http://你的服务地址:端口
cd output
python3 -m pytest api_smoke.py -v
```

脚本里的地址优先读环境变量 **`TEST_BASE_URL`**，未设置则用 spec 里的 `base_url`。

### 3c —— 暂时没有后端，只想看 pytest 能跑完

会快速失败，属正常：

```bash
cd output
TEST_BASE_URL=http://localhost:1 python3 -m pytest api_smoke.py -v --tb=short -x
```

**不要**在后端未就绪、也未改 `TEST_BASE_URL` 时跑长时间全量 `-v`，否则每条用例可能等满超时，像「卡住」。

---

## pytest 也没输出？

和 `generate.sh` 同类问题，落盘再看：

```bash
cd output
python3 -m pytest api_smoke.py -v 2>&1 | tee /tmp/pytest-api-smoke.log
cat /tmp/pytest-api-smoke.log
```

推荐习惯：一律用 **`python3 -m pytest`**，不依赖 PATH 里有没有 `pytest` 命令。

---

## 常见报错对照

| 现象 | 处理 |
|------|------|
| `No module named pytest` | `pip install pytest requests` |
| `No module named yaml` | `pip install PyYAML` |
| 全红 `Connection refused` | 后端没起或 `TEST_BASE_URL` 错；先做 3a |
| `N tests collected` 但 3b 全失败 | 查 path、json 字段、账号是否与你们服务一致 |
| 找不到 `generate.sh` | cd 错目录了 |

## 和演示后端的关系

文档示例里常出现「秒杀财务 / 进销存」类演示系统（`seckill_finance_system`），默认 `http://127.0.0.1:5000`。**它不在 zip 内**，**联系交付方获取**（详见 **`14-FAQ`**）。没有它：

- 仍可做 **3a** 验收  
- 仍可用 AI 从 PRD 生成测试点（不访问接口）  
- 要 **全绿 PASSED** 再指向你自己的服务或演示后端
