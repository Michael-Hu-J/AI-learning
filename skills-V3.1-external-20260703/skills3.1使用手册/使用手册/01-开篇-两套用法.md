# 专业版到底怎么用——先分清两件事

解压后最常见两类问题：

- **「我解压了，第一步点哪里？」**
- **「我开了 Cursor，该跟 AI 说什么？」**

先分清下面两件事，再按 `00-系列导读` 里的 **Day 1** 打勾，后面各篇会顺很多。

> **文档分工**：命令与环境以 zip 内 **`README.md`** 为准；场景与话术以本手册为准。两条线都写在包内 **`START_HERE.md`**，可与本篇对照阅读。

---

## 专业版不是网站，是一个目录

你买到的是 **zip 解压后的文件夹**（一般叫 `skills-专业版V3.0`），里面有：

- 一键生成脚本 `generate.sh`
- 现成模板 `templates/`
- 生成结果 `output/`
- 给 AI 看的技能文档（`api-skills`、`UI-skills`、`testcase-skills` 等）

**没有**必须登录的在线控制台。所有操作在你本机：终端 +（可选）AI 编辑器。

演示用的业务后端（秒杀财务系统 `seckill_finance_system`，即**进销存**演示项目）**不在 zip 里**；**联系交付方获取**，详见 `14-FAQ`。没有后端也能完成「生成脚本 + pytest 收集用例」的验收，见 `02-三分钟跑通.md`。

---

## 第一件事：声明式生成（不依赖 AI）

**你写 Markdown，机器出 pytest。**

流程只有四步：

1. 复制或编写一份 **spec**（带 YAML 头的 Markdown）
2. 在包根目录执行 `./generate.sh 你的文件.md`
3. 在 `output/` 里得到 `.py` 脚本
4. 用 `python3 -m pytest` 运行（推荐写法，见 README）

全程可以**不写 Python**。适合：

- 想先把冒烟跑通的同学
- 想把用例当配置管、要进 CI 的团队
- 暂时不想消耗 AI 编辑器额度的人

典型第一条命令（解压并 `chmod` 之后）：

```bash
./generate.sh templates/api_smoke.md
cd output && python3 -m pytest api_smoke.py --collect-only -q
```

看到 `N tests collected`（无报错即可；内置模板条数以终端为准），就说明「从 spec 到 pytest」这条链是通的。

## 第二件事：AI 技能包（在编辑器里 @ 引用）

**你在 Chat 里用 `@` 指向包里的 SKILL，让 AI 按固定流程干活。**

适合：

- 手里有 PRD、OpenAPI、接口列表，要从需求落到测试点或脚本
- 页面步骤说不清，想结合 URL / 截图生成 Playwright 用例
- 失败后要按统一模板写缺陷、汇总进度

用法要点（细节见第 4 篇）：

- 用 Cursor / Trae 等 **打开技能包根目录**（能看到 `generate.sh` 的那一层）
- 说话时要 **@ 具体路径**，例如 `@testcase-skills/生成/SKILL.md`，不要只说「帮我写用例」

示例话术（可复制，把文件路径换成你的 PRD）：

```text
@testcase-skills/生成/SKILL.md
@examples/prd_mini_seckill_auth.md

按专业版规则生成测试用例，输出到 output/my_testcases.md
```

## 两种方式怎么选

| | 声明式 `generate.sh` | AI + SKILL |
|--|----------------------|------------|
| **要不要 AI** | 不要 | 要（编辑器 Chat） |
| **你要准备什么** | 一份 spec 或改模板 | PRD / OpenAPI / 自然语言描述 |
| **产出** | `output/*.py` | spec、用例 Markdown、脚本、缺陷草稿等 |
| **可控性** | 高，改 YAML 即改脚本 | 中，靠 @ 对的 SKILL 约束 AI |
| **适合谁** | 先跑通、做冒烟 CI | 需求分析、大批量用例设计 |

**不是二选一。** 常见组合：AI 生成 spec 或测试点 Markdown → 你审一眼 → `./generate.sh` 出 pytest → CI 里只跑脚本。

## 和「让 ChatGPT 写个脚本」差在哪

大模型随手也能写 pytest。你已购专业版，价值主要在：

1. **流程写死在 SKILL 里** —— 规划、分析、生成、执行、评审、缺陷，各有入口，减少每次重讲规矩。
2. **声明式与 AI 共用同一套产物形态** —— spec、pytest、缺陷 Markdown 字段一致，方便团队交接。
3. **本地生成器** —— 不依赖模型是否在线，同一份 spec 多次生成结果一致，适合 CI。
4. **扩展能力有边界** —— 接口 / UI / 移动 / 造数 / 压测 / 视觉回归，按 kind 和技能目录分开，不会混成一锅粥。

SKILL 正文和内部规则库在包内 `README.md`、`START_HERE.md` 里；本手册各篇是上面的**场景展开**。

## 包内目录，人只需要认这几个

```
skills-专业版V3.0/
├── generate.sh          ← 你最常用
├── templates/           ← 抄作业
├── output/              ← 生成的脚本、缺陷草稿
├── api-skills/          ← 接口线（给 AI @）
├── UI-skills/           ← 页面线
├── testcase-skills/     ← 用例设计线
├── mobile-skills/       ← App 线
├── bug-reporter/        ← 缺陷模板
├── prompts/常用话术.md  ← 可复制话术
├── README.md            ← 环境与排错（权威）
└── START_HERE.md        ← 三条示例流水线
```

`codegen/` 是生成引擎，**日常使用可以当不存在**。
