# 一个人爽不够：怎么接到你们项目仓库和 CI

> 个人验收清单见 **`00-系列导读.md` 的 Day 1**；命令细节以 zip 内 **`README.md`** 为准。

专业版在个人电脑上跑通只是第一步。团队真正关心的是：

**技能包放哪、业务测试放哪、CI 里跑什么、新人怎么接手。**

---

## 推荐目录分工

| 位置 | 放什么 |
|------|--------|
| **工具库**（可单独仓库或子模块） | `skills-专业版V3.0` 整包：generate、templates、SKILL |
| **业务仓库** | 你们产品的 spec、生成的 pytest、fixtures |
| **CI 工作区** | 检出业务仓库 + 安装依赖 + pytest |

不要把生成物只留在本机 `output/` 而不同步 Git——交接会断。

---

## 新人上手清单（团队版）

1. 安装 Python 3.8+、pip 依赖（见 README 表）  
2. 克隆业务仓库 + 技能包（或文档说明的路径）  
3. 跑通：`generate.sh` + `pytest --collect-only`（第 2 篇）  
4. 读 `START_HERE.md` 三条流水线（用例 / 接口 / UI）  
5. 配 Cursor 打开**技能包根目录**，练习一次 @ `testcase-skills/生成`  
6. 约定：缺陷 Markdown 字段、分支策略、谁审 spec  

---

## CI 里建议跑什么

**阶段 1 —— 不访问外网（PR 必过）**

```bash
python codegen/selftest_bundle.py          # 维护者可选；验证包本身
./generate.sh tests/spec/api_smoke.md
cd output && python3 -m pytest api_smoke.py --collect-only -q
```

**阶段 2 —— 连测试环境（夜间或合并后）**

```bash
export TEST_BASE_URL=$CI_TEST_URL
python3 -m pytest tests/generated/ -v --tb=short
```

**阶段 3 —— UI / App**  
单独 job，装 Playwright 或 Appium agent，别和 API job 硬塞一个镜像。

失败产物：上传 `output/bugs/`、pytest log、Playwright trace（若你们启用）。

---

## 环境变量与密钥

- `TEST_BASE_URL`、`TEST_USERNAME`、`TEST_PASSWORD` 进 CI Secret  
- 数据库造数连接串不进 spec 明文  
- 公众号、对外文档截图**打码**

## 与演示后端的关系

文档示例中的秒杀财务 / 进销存演示系统（`seckill_finance_system`）**不在 zip 内**，**联系交付方获取**。团队若用它培训：

- 单独仓库 / 镜像维护  
- CI 可 docker-compose 起服务再跑 3b 全绿  

没有演示后端，CI 仍可做 **collect-only** 与静态检查，价值是「脚本没写挂」。

---

## 版本升级策略

技能包发 V2.1 时：

1. 看发行说明是否改 schema / SKILL 行为  
2. 在分支跑 `selftest_bundle.py`  
3. 对关键 spec 重新 `generate.sh` 做 diff review  
4. 再合并业务仓库  

避免「只更新 zip、业务 spec 不 regenerate」导致漂移。

## 和 Jira / 禅道 / 飞书

当前主交付是 **Markdown 缺陷** 与 **进度摘要**。对接工单系统可以：

- 人工粘贴  
- 或你们用脚本读 `output/bugs/*.md` 调 API（二次开发，非包内承诺）  

若强依赖「自动建单」，需你们二次开发读 `output/bugs/*.md` 调工单 API（非包内承诺）；见 `14-FAQ` Q8。
