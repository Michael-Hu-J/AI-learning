# 全站页面截图：批量截取 SPA 页面为 PNG

专业版有一个独立的截图模块（`screenshot-skills`），专门用来**批量截取 Web 系统的页面为 PNG 图片**，产出本地文件 + 索引。

它和"视觉回归"不是同一个东西——截图是**采集**，视觉回归是**对比**。截图的结果可以喂给 testcase-skills/生成 做用例分析，也可以单独用来做页面清单。

---

## 什么时候用

| 场景 | 说明 |
|------|------|
| 无 Figma / 静态原型 | 用截图替代"原型截图"输入，给 AI 做用例分析 |
| 页面清单盘点 | 批量截取所有页面，产出 INDEX.md 人工浏览 |
| UI自动化前置 | 截图 → AI 分析页面结构 → 生成 Playwright 脚本 |
| 多角色权限验证 | 分角色截图，对比不同角色的页面差异 |

---

## 快速使用

### A. 通用站点（路由清单）

```bash
pip install playwright pyyaml
playwright install chromium

python screenshot-skills/全站截图/scripts/crawl_and_capture.py \
  --base-url http://localhost:8080 \
  --out-dir output/site-screenshots/demo \
  --routes-file screenshot-skills/全站截图/templates/routes.example.txt \
  --auth-profile screenshot-skills/全站截图/templates/auth_ui_login.example.yaml \
  --viewport 1440x900 \
  --wait-ms 1500
```

### B. 管理台类系统（侧栏菜单 + 弹窗）

管理台通常有侧栏导航，自动爬取侧栏链接更高效：

```bash
# 首次：手动登录并保存会话
python screenshot-skills/全站截图/scripts/capture_console_sidebar.py \
  --base-url http://<internal-console-host>/console \
  --start-menu 消息中心 \
  --manual-login --headed \
  --storage-state output/.auth/console_auth.json \
  --out-dir output/site-screenshots/console \
  --capture-dialogs

# 后续：复用登录态
python screenshot-skills/全站截图/scripts/capture_console_sidebar.py \
  --base-url http://<internal-console-host>/console \
  --start-menu 消息中心 \
  --storage-state output/.auth/console_auth.json \
  --routes-file screenshot-skills/全站截图/templates/routes_console_example.txt \
  --out-dir output/site-screenshots/console \
  --capture-dialogs
```

弹窗规则：列表页自动点击"新增/编辑/查看/导出"等按钮，截取 `[role=dialog]` 区域。

## 工作流程

### Step 0：澄清输入

| 项 | 必填 | 说明 |
|----|------|------|
| base_url | 是 | 测试环境根地址 |
| 登录方式 | 多数 SPA 需要 | 表单登录 / Cookie / Storage State |
| URL 来源 | 三选一+ | 路由清单 / 侧栏 / 站内爬取 |
| 规模 | 建议 | 默认 --max-pages 500，大系统先小批试跑 |

### Step 1：选择 URL 发现方式

| 方式 | 参数 | 适用 |
|------|------|------|
| 路由清单（推荐） | `--routes-file routes.txt` | 前端路由或菜单 path |
| 侧栏链接 | `--crawl-menu` | 侧栏 nav / aside |
| 站内 BFS | `--crawl-bfs --max-depth 2` | 页面间跳转较多 |
| 组合 | 清单 + 爬菜单 | 提高覆盖率 |

动态 SPA 无法一次性保证 100% 覆盖，Tab / 抽屉 / 弹窗建议单独写入 routes。

### Step 2：执行截图

| 选项 | 说明 |
|------|------|
| 默认 | 视口截图（1440x900） |
| `--full-page` | 长页面全高截图 |
| `--wait-ms` | 渲染等待时间 |
| `--ready-selector` | 等待特定元素出现 |
| `--headed` | 调试模式，显示浏览器窗口 |

### Step 3：交付物

```
output/site-screenshots/<host>/
├── pages/*.png
├── manifest.json
└── INDEX.md
```

- `manifest.json`：每页的 URL、标题、状态码、截图路径
- `INDEX.md`：带截图预览的索引表，人工浏览用

### Step 4：接入用例流水线（可选）

截图本身不是用例，但可以辅助用例生成：

1. 按模块划分子目录
2. 调用 testcase-skills/生成，把截图作为输入
3. 结合 UI-skills/分析 从图片中提取页面结构

## URL 发现方式详解

### 路由清单（推荐）

创建一个文本文件，每行一个路由：

```
/
/login
/dashboard
/products
/products/create
/orders
/orders/create
/users
/finance/accounts
/finance/transactions
```

优点：精确控制、覆盖明确、可重复。

### 侧栏菜单爬取

适合管理台类系统，侧栏有完整的导航链接：

```bash
python capture_console_sidebar.py \
  --base-url http://console.example.com \
  --start-menu 消息中心 \
  --crawl-menu
```

脚本会自动：
1. 打开起始菜单项
2. 遍历侧栏所有链接
3. 对每个页面截图

### 站内 BFS 爬取

适合页面间跳转较多的系统：

```bash
python crawl_and_capture.py \
  --base-url http://example.com \
  --crawl-bfs \
  --max-depth 2
```

从起始页开始，BFS 遍历所有站内链接，最多爬取 2 层深度。

### 组合方式

实际使用中，建议**路由清单 + 侧栏爬取**组合：

```bash
# 先用侧栏爬取发现所有菜单页面
python capture_console_sidebar.py --crawl-menu --out-dir output/screenshots/console

# 再用路由清单补充非菜单页面（如弹窗、详情页）
python crawl_and_capture.py --routes-file routes_extra.txt --out-dir output/screenshots/extra
```

## 大规模系统注意事项

| 事项 | 建议 |
|------|------|
| 首次跑 | 先跑 20 页验证登录与渲染，再扩大规模 |
| 同 path 不同 query | 会分别截图，必要时收敛 routes |
| 多角色权限 | 分角色多次运行，输出到不同子目录 |
| 截图脱敏 | 截图脱敏后再入库，manifest.json 不含敏感字段 |
| 执行方式 | 当前脚本为串行执行，稳定性优先 |

## 和视觉回归的区别

| | 全站截图 | 视觉回归 |
|--|---------|---------|
| 用途 | 批量采集页面为 PNG | 对比基准图，检测 UI 回归 |
| 产出 | PNG + INDEX.md | 相似度分数 + 差异图 |
| 依赖 | Playwright | Playwright + pillow + scikit-image |
| 后续 | 喂给 AI 做用例分析 | 直接判定 PASS/FAIL |

视觉回归见第 10 篇（扩展-造数压测视觉.md），本篇只讲截图采集。

## 质量检查清单

截图完成后，检查：

- [ ] manifest.json 中 failed ≈ 0 或已记录原因
- [ ] INDEX.md 与 pages/ 数量一致
- [ ] 核心流程页面（登录、首页、主菜单）均有截图
- [ ] 截图路径符合 output/ 约定，未混入敏感数据
