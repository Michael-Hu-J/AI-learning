# 接口测试：从 OpenAPI 到能跑的 pytest，你要准备什么

> 环境变量、`run_pytest.sh` 行为以 zip 内 **`README.md`** 为准。

接口线是专业版里用得最多的一条。可以**完全声明式**，也可以 **AI 出 spec 再 generate**。

---

## 推荐流水线（对外说法）

```
分析（00–03）→ 规划 → 执行（01–04）→ 必要时 自我修复
```

人不用背编号。记两个入口即可：

- 看流程：`api-skills/索引.md`  
- 让 AI 写脚本 / spec：`@api-skills/执行/SKILL.md`（或包内执行目录下的 `SKILL.md`）

---

## 你可以给 AI 的输入

| 输入 | 说明 |
|------|------|
| OpenAPI / Swagger JSON 或 YAML | 最稳，路径、方法、字段齐 |
| Postman 导出 | 可先让 AI 转成 spec 结构 |
| 接口清单（表格） | 适合冒烟集 |
| 自然语言 | 要说清 base_url、方法、路径、关键 body |

示例话术：

```text
@api-skills/执行/SKILL.md

OpenAPI 文件：@docs/openapi.yaml
base_url: https://test.example.com
请生成 api_pytest spec 到 output/api_contract_smoke.md，
并说明如何用 generate.sh 生成 pytest。
```

---

## 不依赖 AI 的冒烟

包内模板可直接生成：

```bash
./generate.sh templates/api_smoke.md
# 或秒杀示例命名（若有）
./generate.sh templates/seckill_api_smoke.md
```

改 `base_url` 和 `cases` 后重新 generate。环境变量：

```bash
export TEST_BASE_URL=http://你的服务:端口
export TEST_USERNAME=admin      # 部分模板用
export TEST_PASSWORD=admin123
./run_pytest.sh output/api_smoke.py -v
```

`run_pytest.sh` 在失败时可将摘要写入 `output/bugs/`（见第 11 篇）。

---

## 产物放哪里

| 类型 | 建议位置 |
|------|----------|
| spec（源） | 技能包 `output/` 或**业务仓库** `tests/spec/` |
| 生成的 pytest | 与 spec 同目录或 `tests/api/` |
| 缺陷草稿 | `output/bugs/` |

团队规范建议：**业务代码仓库**放可跑的 pytest；技能包目录当工具链与模板库，避免和业务分支搅在一起。

---

## 失败时先自查，再谈「修」

常见顺序：

1. 服务是否启动、`TEST_BASE_URL` 是否正确  
2. `path`、HTTP 方法是否写反  
3. `json_body` 字段名、类型是否与契约一致  
4. 鉴权头、token 是否过期（模板里常有 `headers` 占位）  

仍失败且确认是**脚本/断言**问题，再 @ `api-skills/自我修复/SKILL.md`。自我修复的具体策略在包内 SKILL 里。

---

## 和用例设计线的关系

- 只有接口列表、没有 PRD：可直接执行线出 spec。  
- 有 PRD：建议先 `testcase-skills/生成`，评审后把 P0 场景交给执行线。  

避免跳过评审直接全量生成 pytest，维护成本会爆。
