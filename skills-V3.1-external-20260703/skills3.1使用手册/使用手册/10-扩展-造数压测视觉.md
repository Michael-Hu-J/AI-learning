# 不止接口和页面：造数、压测、视觉回归怎么用

> 各 kind 完整依赖见 zip 内 **`README.md` 依赖表**；字段见 `python codegen/run_spec.py --print-schema`。

专业版除了 `api_pytest` 和 `ui_pytest_playwright`，还有三类**扩展 kind**，适合专项场景。

它们同样走：**改 spec → `./generate.sh` → 跑对应工具**。

---

## 一、data_factory —— 造测试数据

**什么时候用**

- 联调前要在库里铺用户、订单、库存  
- 自动化前置数据重复劳动  
- 多环境要可重复的数据脚本  

**依赖（典型）**  
`pymysql` 等，以模板注释为准。

**怎么用**

```bash
cp templates/data_factory.md my_seed.md
# 改数据库连接、表、插入逻辑描述
./generate.sh my_seed.md
```

生成的是可执行的 Python 造数脚本，不是「在聊天里给你几条 INSERT」。

**注意**

- 账号密码、库地址不要提交到公开仓库；用环境变量或 CI Secret。  
- 造数与接口断言是两件事：造数失败不等于接口 bug。

---

## 二、perf_test —— 接口压测（Locust）

**什么时候用**

- 冒烟级：某几个核心接口在发布前「扛一下」  
- 对比两次构建的 QPS / P95（需你们自己定基线）  

**什么时候不够**

- 端到端容量规划、长时间稳定性、监控大盘——仍需专业性能团队与平台。

**怎么用**

```bash
pip install locust
./generate.sh templates/perf_test.md
# 按生成脚本说明启动 Locust（见 output 内注释或 README）
```

**边界**  
专业版帮你**从 spec 落到 Locust 脚本骨架**；压测场景设计、指标口径、报告解读仍要人把关。

---

## 三、visual_regression —— UI 截图对比

**什么时候用**

- 大改版后怕「布局挤歪、按钮没了」
- 功能用例已绿，仍要防 CSS/组件回归

**依赖**
pytest-playwright、pillow、scikit-image 等（见包内 README 依赖表）。

**怎么用**

```bash
pip install pytest-playwright pillow scikit-image
playwright install chromium
./generate.sh templates/visual_regression.md
```

首次运行往往要**录基准图**；后续失败可能是真回归，也可能是数据变化导致页面不同——需要人工判读。

**和功能 UI 的分工**

| | ui_pytest_playwright | visual_regression |
|--|----------------------|-------------------|
| 断言 | 点击、文案、跳转 | 像素/结构相似度 |
| 维护 | 业务步骤变要改步骤 | 基准图要更新策略 |

> **注意**：「全站截图」和「视觉回归」不是同一个东西。截图（`screenshot-skills`）是**批量采集页面为 PNG**，产出 INDEX.md 供人工浏览或喂给 AI 做用例分析；视觉回归是**对比基准图**，判定 UI 是否回归。截图模块见第 18 篇（全站截图.md）。

---

## 三合一最小工作流

```
1. data_factory 铺底数据
2. api_pytest / ui_pytest 功能回归
3. 发版前对关键页跑 visual_regression
4. 核心接口可选 perf_test 冒烟压测
```

不必每次发版四件套全跑；在 `testcase-skills/规划` 里定「本迭代做哪几类」。

---

## AI 能不能写这三种 spec

可以，但要 @ 对意图：

- 造数 → 说明表结构、约束，引用 `testcase-data-generator` 或相关模板  
- 压测 → 说明接口、并发目标，引用 `special-testing`（若包内有）  
- 视觉 → 给出 URL 列表与视口，引用 UI/专项 SKILL  

仍建议人审：**连接串、并发数、基准图范围**。
