# 从 PRD 到测试点：专业版推荐的一条龙

很多团队用专业版，第一诉求不是 pytest，而是：

**「需求来了，测试点能不能别从零憋？」**

这条线走 `testcase-skills`，**不依赖后端**也能完成大半——PRD 在本地或仓库里即可。

---

## 四段分工（各解决什么）

| 阶段 | 目录 | 干什么 |
|------|------|--------|
| **规划** | `testcase-skills/规划` | 测什么、不测什么、优先级、节奏 |
| **分析** | `testcase-skills/分析` | 拆模块、主流程、风险点、场景表 |
| **生成** | `testcase-skills/生成` | 从需求产出结构化测试点 / 用例 Markdown |
| **评审** | `testcase-skills/评审` | 上线前抽检：像不像测试、有没有漏 |

不是每次都要跑满四段。需求很清晰时，常直接从 **生成** 开始；大版本发布前加 **评审**。

---

## 四段各自解决什么

### 规划（testcase-skills/规划）

需求还粗、分析还没往下拆的时候，先用规划把**测哪些、大概多久、先动哪块**说清楚。

**适用**：新版本发布前需要总体测试方案；多团队并行需要统一优先级语言；资源有限需要风险驱动的裁剪策略。

**可跳过**：单条缺陷验证或极小规模改动且范围已在工单写死。

**输出**：范围锚定、风险画像、测试类型配比、节奏与里程碑、资源与工具。

### 分析（testcase-skills/分析）

将含糊需求拆成**可测场景、边界、规则清单**；复杂需求可先 RAG 检索历史经验。

**适用**：只有功能名、规则复杂、要对接口、要看历史用例。

**可跳过**：需求写得很死（前置、步骤、期望都齐），或只有一个极简无分支操作。

**输出**：场景列表、边界点、规则列表、open_questions。

### 生成（testcase-skills/生成）

从需求产出结构化测试点 / 用例 Markdown。这是四段中最重的一段，包含 RAG 检索、边界值、通用覆盖矩阵、追溯表、评审表。

**默认流程会先 RAG 再写用例**。详见第 17 篇（RAG知识库与缺陷同步.md）。

### 评审（testcase-skills/评审）

批量生成或大批量改动之后，执行自动化或交给业务之前，过一道评审：查漏、改措辞、把优先级捋顺。

**值得评审**：发布窗口临近或审计要留痕；需求一改牵动一串用例；步骤说不清、标签乱、critical 满天飞。

**可偷懒**：零星一条草稿不影响主线的。

## 路径 A：最小可复制流程（无后端）

在 AI 编辑器打开包根目录，Chat 中：

```text
@testcase-skills/生成/SKILL.md
@examples/prd_mini_seckill_auth.md

按专业版规则生成测试用例，输出到 output/seckill_auth_testcases.md
```

完成后：

1. 打开 `output/seckill_auth_testcases.md` 人工过一遍  
2. 与包内黄金样例 `examples/output_seckill_auth_testcases.md` **对照结构**（不要求一字相同）  
3. 满意再进入接口/UI 自动化

### 需求很粗怎么办

先：

```text
@requirement-modeling/SKILL.md

（附上你的 PRD 或需求片段）

请输出范围、假设、不测项，我再进入用例生成。
```

### 发布前要评审

```text
@testcase-skills/评审/SKILL.md
@output/seckill_auth_testcases.md

按评审 SKILL 给修改意见清单，不要直接改文件。
```

## 什么叫「像测试点，不像功能介绍」

下面三条是自检原则（详细校验在包内 `testcase-skills/生成/references/`，由 AI 读取）：

1. **可执行** —— 能写出操作步骤和预期，而不是「系统应支持登录」。  
2. **有边界** —— 长度、次数、权限、状态异常要落到具体值或场景。  
3. **能失败** —— 一条测试点应存在「做对 / 做错」的判定，而不是复述 PRD 原句。

若 AI 输出满篇「用户可以使用某某功能」，让它按 `@testcase-skills/生成/SKILL.md` 重写，或你切到评审 SKILL 打回。

---

## 层次别堆太深也别太浅

专业版生成 SKILL 会按功能复杂度控制 **2～4 层** 标题，避免：

- 一层罗列几十个 bullet（没法排期）  
- 五层目录下只有一句话（维护成本高）

具体层次模式在包内 `testcase-skills/生成/references/`，由 AI 自动读取，你无需背。

---

## 和声明式、接口线的衔接

```
PRD →（AI）测试点 Markdown → 人审 → 挑 P0 场景 → api/UI spec → generate.sh → pytest
```

测试点本身**不必**先变成 Python；评审通过后再让 `@api-skills/执行` 或手写 spec 更稳。
