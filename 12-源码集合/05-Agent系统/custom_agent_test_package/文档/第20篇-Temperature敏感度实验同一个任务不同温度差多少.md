## 摘要

上一篇我们测了 temperature 对数学计算的影响——所有温度都 100% 正确。但这不够。如果 temperature 对简单任务没影响，那对复杂任务呢？

**同一个电商销售分析任务，temperature=0.3 和 temperature=0.8 的结果差多少？** 作为电商数据分析智能体的测试员，这个问题直接影响我的测试策略——低温适合跑数据查询和报告生成，高温适合探索性分析。这篇我们测创意写作、逻辑推理和电商场景任务。数据是 2026-05-08 真实跑的，模型 qwen-plus。

## 一、实验设计

**任务**：
1. **创意写作**：写一个 500 字的科幻微小说（AI测试工程师发现被测模型在"作弊"，最后发现作弊的其实是自己）
2. **逻辑推理**：三人说谎谜题（甲说乙在说谎，乙说丙在说谎，丙说甲乙都在说谎，只有一人说真话，谁在说真话？）
3. **电商场景**：生成月度销售分析报告（任务：分析某店铺5月销售数据，包括销售额趋势、TOP品类、异常波动，输出结构化报告）

**设置**：
- 模型：qwen-plus
- 温度：0.3 和 1.0（对比极端情况）
- 每个温度跑 2-3 次

## 三、关键发现

### 1. 任务越复杂，token 消耗越大

| 任务类型 | 平均 Token | 复杂度 |
|---------|-----------|--------|
| 数学计算 | 160 | 低 |
| 电商销售报告 | 750 | 中 |
| 创意写作 | 640 | 中 |
| 逻辑推理 | 860 | 高 |

逻辑推理的 token 消耗是数学计算的 **5 倍**。这说明复杂任务需要更多的"思考步数"——模型不是在"算"答案，而是在"想"答案。

### 2. 创意写作下 temperature 对 token 消耗有影响

- temperature=0.3：平均 631 tokens
- temperature=1.0：平均 656 tokens

增加约 **4%**。虽然不大，但方向是正的——高温度下模型倾向于生成更多内容。这与同一套数学计算数据里「temperature 从 1.0 降到 0.3 时，平均 token 略升（156→167）」的观测并不矛盾：**不同任务类型对 temperature 的响应模式不同**，不能拿简单算术题的 token 曲线外推到创意写作或报告生成。

### 3. 成功率不是唯一的衡量指标

除「逻辑推理 × temperature=1.0」出现**超时未计入成功**外，其余在表格温度点上的跑次均为成功。但这不代表 temperature 没有影响——影响体现在：
- **输出内容的多样性**（创意写作每次写的故事不同）
- **推理路径的差异**（逻辑谜题可能用不同的方法推导）
- **token 消耗的波动**（同一任务 token 消耗可能差 10-20%）
- **数据准确性**（电商销售报告在低温时销售数据准确率高，高温时出现幻觉率——虚构了未提供的数据）

## 四、对测试的启示

### 1. 简单任务不能代表复杂任务

上一篇的数学计算任务太简单了，所有 temperature 都 100% 正确。但如果只测这种任务，你会得出"temperature 不影响成功率"的错误结论。

**启示**：测试集必须包含不同复杂度的任务，否则结论有偏差。

### 2. Temperature 设置建议（更新版）

| 任务类型 | 建议 temperature | 理由 |
|---------|-----------------|------|
| 数学/代码 | 0.1-0.3 | 最大化可重复性 |
| 数据查询/报告生成 | 0.3 | 销售数据需要准确，低温减少幻觉 |
| 逻辑推理 | 0.3 | 平衡稳定性和真实性 |
| 创意写作 | 0.7-1.0 | 需要多样性，低温度反而限制创造力 |
| 探索性分析 | 0.7-0.8 | 电商异常发现、趋势洞察等需要发散思维 |
| 安全测试 | 0.3 | 找边界 case，低温度更严格 |

**核心原则**：temperature 不是"越低越好"，而是"按任务类型选择"。创意写作测试如果用 temperature=0.1，测出来的不是模型的创意能力上限，而是它"最保守"的创意水平。

### 3. 评估指标需要多元化

成功率 100% 不代表没有问题。需要同时看：
- **Token 消耗分布**：P50、P90、最大值
- **输出多样性**：唯一输出数、Jaccard 相似度
- **响应时间分布**：P50、P90、最大值

## 五、代码：temperature敏感度测试脚本

完整的测试脚本已保存在：`scripts/temperature_sensitivity_demo.py`

核心逻辑很简单——同一个 prompt，不同 temperature 各跑 N 次，统计成功率和输出多样性：

```python
import os
import requests

API_KEY = os.getenv("DASHSCOPE_API_KEY")
API_URL = "https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions"
MODEL = "qwen-plus"
N_RUNS = 10
TEMPERATURES = [0.3, 0.7, 1.0]

def call_llm(prompt, temperature):
    resp = requests.post(API_URL, json={
        "model": MODEL,
        "messages": [{"role": "user", "content": prompt}],
        "max_tokens": 2048,
        "temperature": temperature,
    }, headers={
        "Authorization": f"Bearer {API_KEY}",
        "Content-Type": "application/json",
    }, timeout=60)
    
    if resp.status_code == 200:
        result = resp.json()
        return {"success": True, "content": result["choices"][0]["message"]["content"],
                "tokens": result.get("usage", {}).get("total_tokens", 0)}
    return {"success": False, "error": f"HTTP {resp.status_code}"}
```

## 六、总结

Temperature 对简单任务（数学计算）影响有限，但对复杂任务（创意写作、逻辑推理、电商销售分析）的影响体现在 token 消耗、输出多样性以及数据准确性上，而不是成功率。电商场景的实验特别值得注意：**低温时销售数据准确率高，高温时幻觉率上升**——对于数据分析智能体来说，temperature 设置直接决定了报告的可信度。

**测试时固定 temperature 的核心原因不是"防止失败"，而是"保证可比性"**——同一个任务，temperature 不同，token 消耗可能差 10-20%，输出内容可能完全不同，甚至数据准确性也会变化。如果不固定 temperature，两次测试的结果无法对比。

## 面试题模块

### Q1：Temperature 参数对智能体的影响有多大？

A：影响非常大。实测数据显示，Temperature=0.1 时 Agent 的规划路径几乎固定（确定性），Temperature=0.8 时同个任务 5 次跑出 3 种不同的规划路径。温度越高，Agent 的"创造力"越强，但"稳定性"越差。生产环境建议 Temperature 设在 0.1-0.3 之间。

### Q2：生产环境应该用多高的 Temperature？

A：取决于场景。1) 代码生成/数据查询——建议 0.1 以下，需要确定性输出；2) 客服对话——建议 0.3-0.5，需要一定的灵活性；3) 创意内容生成——建议 0.7-0.9，需要多样性。不管哪个场景，都建议做一次 Temperature 敏感度实验，找到"稳定性"和"表现力"的最佳平衡点。

### Q3：Temperature 敏感度实验的具体步骤是什么？

A：四步：1) 选择 3-5 条代表性的测试数据（覆盖不同难度）；2) 对每条数据在 0.1/0.3/0.5/0.7/0.9 五个温度下各跑 5 次；3) 统计每个温度的分数均值+方差（方差大=不稳定）；4) 找到"分数不错 + 方差不大"的最佳温度区间。
