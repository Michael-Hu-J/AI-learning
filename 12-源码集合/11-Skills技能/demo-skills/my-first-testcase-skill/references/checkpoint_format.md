# 检查点写法

## 合格示例

- 输入错误密码时，页面提示「账号或密码错误」，且不跳转 `/home`
- 第 5 次密码错误后，再次登录返回「账号已锁定，请 30 分钟后重试」
- 手机号为 10 位时，提交按钮不可点或提示「手机号格式错误」
- 订单金额为 0 元时，提交接口返回 HTTP 400，响应体含 `INVALID_AMOUNT`

## 不合格示例（必须改写）

| 不合格 | 问题 |
|--------|------|
| 系统应正常运行 | 无法 PASS/FAIL |
| 登录功能可用、体验良好 | 主观、不可观测 |
| 支持多种登录方式 | 未说明具体方式 |
| 界面美观、响应迅速 | 无判定标准 |

## 改写口诀

**谁 + 在什么条件下 + 做什么 + 期望看到什么（可观察）**

## 落笔前三问

1. 验证的是哪一个具体行为？
2. 测试员能否客观判定通过/失败？
3. 预期是否写到了可观测的结果（文案、状态码、跳转 URL、数据库字段）？
